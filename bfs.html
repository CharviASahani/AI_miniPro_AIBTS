Behind The Search

BFS thinks in layers.

Starting from A, BFS first discovers its immediate neighbors. Only after those nodes are processed does it continue to the next level. This is why BFS can find a shortest path in an unweighted graph.

01

Enqueue

Put the starting node into the queue and mark it as discovered.

02

Dequeue

Remove the oldest node from the front of the queue.

03

Discover

Add unvisited neighbors to the back of the queue.

04

Repeat

Continue level by level until the target is found or the queue becomes empty.

Understand the algorithm

What makes BFS different?

Breadth-First Search explores nodes according to their distance from the starting point. Its queue controls the order in which discovered nodes are processed.

📚

First In, First Out

The queue ensures that nodes discovered earlier are processed before nodes discovered later.

🌊

Layer by layer

BFS expands outward from the starting node like a wave, visiting nodes at increasing distances.

🎯

Shortest path

In an unweighted graph, the first time BFS reaches a node, it has found a path with the minimum number of edges from the start.

🧩

Visited set

Nodes are marked when discovered so the search does not repeatedly add the same node to the queue.

Implementation

See the code behind BFS.

This is the core idea used by the interactive search above. The queue drives the order of exploration.

bfs.js 
function bfs(graph, start, target) {
const queue = [start];
const visited = new Set([start]);

while (queue.length > 0) {
    const current = queue.shift();

    if (current === target) {
        return current;
    }

    for (const neighbor of graph[current]) {
        if (!visited.has(neighbor)) {
            visited.add(neighbor);
            queue.push(neighbor);
        }
    }
}

return null;


}
